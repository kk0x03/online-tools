## Context

当前 ChatPanel 组件中，`sendMessage()` 每次都会自动构造一个包含编辑器代码的 `contextMsg` 并附加到 API 消息末尾。用户无法控制是否包含编辑器内容。多轮对话历史通过 `messages.value` 全量发送，这个行为保持不变。

## Goals / Non-Goals

**Goals:**
- 输入框区域提供"引用编辑器代码"的切换按钮
- 引用时显示带代码预览的 chip 标签
- 编辑器代码仅在用户主动引用时才发送给 API
- 多轮对话历史默认加载

**Non-Goals:**
- 不做历史对话加载的选择控制（保持默认全部加载）
- 不做 token 用量优化或消息截断
- 不做斜杠命令系统

## Decisions

### 引用状态管理

使用组件内 `ref<boolean>` 管理引用状态。不持久化到 localStorage — 每次打开对话框默认不引用，用户需要时手动点击。

理由：引用编辑器是即时意图，不需要跨会话记忆。

### UI 布局

输入框上方增加引用标签区域，输入框右侧增加引用按钮。

```
┌──────────────────────────────┐
│ 📋 graph TD A[开始]-->... ×  │  ← 引用时的 chip
│ ┌──────────────────────┐     │
│ │ 输入框               │     │
│ └──────────────────────┘     │
│               [📎] [发送]    │
└──────────────────────────────┘
```

chip 内显示编辑器代码前 30 个字符的预览，右侧 × 按钮取消引用。

### 消息构建逻辑

- 无引用时：`apiMessages = 历史消息`（无编辑器上下文）
- 有引用时：`apiMessages = 历史消息 + 编辑器代码 contextMsg`（在最后一条用户消息后插入）

## Risks / Trade-offs

- **默认不引用可能让新用户困惑** → 输入框 placeholder 可以提示"点击 📎 引用编辑器代码"
- **chip 占用输入框上方空间** → chip 高度固定一行，代码截断显示，不会影响布局
